# ElasticSearch
Trong ELK stack, Logstash là dịch vụ thu thập data chỉ được triển khai phía client, Kibana visualize data. Hiện dùng Filebeat thay cho Logstash vì nó nhẹ hơn và tốt hơn.
Filebeat là 1 trình thu thập dữ liệu độc lập với ECK và có thể hỗ trợ ECK bằng cách thu thập data và gửi đến elastic search hay Logstash, Kibana để lưu.
Elastic search k thể thay thế db vì k có tính ACID, chỉ search record nhanh, k có quan hệ complex relational giữa các bảng. SQL cũng k thay thế ES vì full text search của ES rất mạnh, còn SQL tốn thêm nhiều memory khi thêm index.
Elastic Search chỉ dùng khi cần full-text search, realtime analytics với unstructured data. 

ECK (Elastic Cloud on Kubernetes): Có công ty gọi là dùng ECK thì hiểu là dùng các sản phẩm của Elastic Stack (Elasticsearch, Kibana, Beats, Logstash) deploy trên K8s. 
K8s quản lý các container chạy các tool đó, dùng sẽ dễ hơn nhiều so với deploy thủ công.

-> Cài đặt: 
- Dùng cloud
- Dùng docker cài ES và Kibana:
docker network create elastictest => tạo 1 network vì ElasticSearch và Kibana tương tác với nhau trong cùng 1 mạng host cung ra ngoài
docker pull docker.elastic.co/elasticsearch/elasticsearch:8.8.2 => vào dockerhub cho phiên bản mới nhất
docker run --name es-test --net elastictest -p 9200:9200 -p 9300:9300 -e "discovery.type=single-node" -it docker.elastic.co/elasticsearch/elasticsearch:8.8.2
Vào localhost:9200 để check elasticsearch đang chạy.
Mật khẩu lưu trong logs, để lấy có thể ghi ra file "docker logs <hash> > test.txt", search từ khoá password, username default là "elastic"

docker pull docker.elastic.co/kibana/kibana:8.8.1 => cài kibana
docker run --name kib-test --net elastictest -p 5601:5601 docker.elastic.co/kibana/kibana:8.8.1
Mở với http://localhost:5601/?code=622883 Khi cài elasticsearch nhận được token paste vào kibana để tương tác bằng giao diện.

# Viết query với _search
_search dùng GET hay POST đều được

VD chỉ lấy trường @timestamp:
GET test/_search
{
  "query": {
    "match_all": {}
  },
  "fields": [
    "@timestamp"
  ], 
  "_source": false, // Or [<liệt kê các trường ra>]
  "sort": [
    {
      "@timestamp": {
        "order": "desc"
      }
    }
  ]
}

VD search mặc định là OR với các từ juve OR help OR striker trong trường phrase:
PUT players => tạo index cho players, tương tự như "PUT /players"
Sau khi tạo index thì có thể tìm kiếm:
POST players/_search
{
  "query": {
    "match": {
      "phrase": "juve help striker"
    }
  }
}

VD search với AND:
POST players/_search
{
  "query": {
    "match": {
      "phrase": {
        "query": "juve help striker",
        "operator": "and"
      }
    }
  }
}

VD search bằng OR khớp 2 từ, nếu khớp 3 từ thì hệt như AND:
POST players/_search
{
  "query": {
    "match": {
      "phrase": {
        "query": "juve help striker",
        "minimum_should_match": 2
      }
    }
  }
}

VD search theo 2 trường name và phrase or 2 từ wood và juve:
POST players/_search
{
  "query": {
    "multi_match": {
      "query": "wood juve",
      "fields": ["name", "phrase"]
    }
  }
}

VD tìm kiếm đủ 1 cụm từ và phải đúng thứ tự như các từ riêng biệt:
POST players/_search
{
  "query": {
    "match_phrase": {
      "phrase": "help striker juve"
    }
  }
}

VD dùng slop linh hoạt:
POST players/_search
{
  "query": {
    "match_phrase": {
      "phrase": "help juve",
      "slop": 1 // chỉ định có max 1 từ nữa được xuất hiện giữa 2 từ help và juve giúp tăng độ linh hoạt của search
    }
  }
}

VD search chỉ cần có chứa đúng cụm từ:
POST players/_search
{
  "query": {
    "match_phrase_prefix": { // tìm kiếm bắt đầu bằng cụm từ nào
      "phrase": "help juv",
      "max_expansions": 2 // số lượng các từ khớp trong từ điển mà ta lấy, default nó là 50 phần tử
    }
  }
}
Giả sử trường phrase có các giá trị:
help juventus
help juvenile
help juvencio
help juvan
help jump
thì nó lấy 2 từ đầu tiên là help juventus và help juvenile, bỏ qua các từ còn lại vì max_expansions = 2



# Thao tác trên kibana
-> Tab Devtool:

Add 1 record vào index test (id và version sinh tự động như mongodb):
POST test/_doc
{
  "username": "Hello"
}
=> test là chỉ mục tự tạo nếu chưa có, mọi tương tác đều phải xác định tác động tới 1 chỉ mục nào hay tác động toàn bộ.

Add multi vào index test:
POST test/_bulk
{"create": {}}
{"@timestamp": "2022-10-28", "username": "cr7"}
{"create": {}}
{"@timestamp": "2022-10-27", "username": "cr8"}

Add multi vào nhiều index khác nhau, url k cần xđ index nữa
POST _bulk
{"create": { "_index": "test" }}
{"@timestamp": "2022-10-28", "username": "cr7"}
{"create": { "_index": "facebook" }}
{"@timestamp": "2022-10-27", "username": "cr8"}

Add kèm update:
1) PUT test/_doc/100001
{
  "user": "cr7"
}
=> Khi thêm sẽ tự động dùng _id là 100001, id này đã tồn tại thì thành update
2) PUT test/_create/100001
{
  "user": "cr7"
}
=> Chưa có thì tạo, id có r thì báo lỗi
3) PUT test/_doc/100004?op_type-create
{
  "user": "cr7"
}
=> Thành dùng _create ở case 2

Lấy mọi index trong elasticsearch cluster:
GET _cat/indices
=> Tương tự khi convert sang rest api: curl -XGET https://localhost:9200/_cat/indices

Search lấy mọi record với trường timestamp giảm dần
GET test/_search
{
  "query": {
    "match_all": {}
  },
  "sort": [
    {
      "@timestamp": {
        "order": "desc"
      }
    }
  ]
}

Lấy nhiều bản ghi match
GET _mget
{
  "docs": [
    {
      "_index": "test",
      "_id": 100001,
      "_source": ["user"]
    }, {
      "_index": "test",
      "_id": 100002
    }
  ]
}

VD Thêm 1 kiểu mới vào doc của custom endpoint:
PUT test/_mapping
{
  "properties": {
    "number": {
      "type": "integer"
    },
    "birth_date": {
      "type": "date",
      "format": "dd/MM/yyy"
    }
  }
}

GET / => chính là localhost::9200

--> URL: https://www.elastic.co/guide/en/elasticsearch/reference/current/docs-bulk.html
Lệnh <endpoint> {<body dạng json>}
VD: HEAD test/_doc/100001 => check bản ghi tồn tại
HEAD test => check có chỉ mục test hay không

Các endpoint có lúc dùng trong body, có lúc dùng trong url path, có lúc dùng trong url search. VD xóa bản ghi:
1) DELETE test/_doc/100001
2) POST test/_delete_by_query
{
  "query": {
    "match": { "user": "cr7", "_id": "100001" }
  }
}
Có thể xóa multi record của index với DELETE _bulk

--> Tổng hợp các endpoint hay:
_doc và _search là 2 endpoint hay dùng nhất

GET test/_mapping => lấy _mapping của index custom là thông tin các trường của index đó. Nếu ta k định nghĩa thì các trường có type xđ default
PUT test/_create/1001 {<body>} => tương tự PUT test/_doc/1001 {<body>}
GET test/_doc/100001?_source=user,uid => _source trong trường search lọc ra field cần lấy
GET test/_doc/100001?filter_path=_source => filter_path bảo lấy toàn bộ _source
GET test/_count => _count lấy số bản ghi của index

_settings => endpoint chỉnh sửa config
_create => Chưa có thì tạo, có r thì báo lỗi
_mget => lấy multi record
